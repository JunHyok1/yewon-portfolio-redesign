Fasoo Design System Auto-Generator

Software Engineer Intern · Fasoo AI, Seoul · Jun – Aug 2026

A Figma-to-Flutter pipeline that generates Fasoo Design System components.

  • Accuracy 83.1% → 99.5%

Problem

Fasoo's design system centralized UI components, but keeping Figma and code in sync was still manual. After each design change, a developer had to find what changed, update the Flutter library by hand, and review it, and mismatches with the design still reached QA. Accuracy dropped as components grew, and repeated rounds of fixes and designer checks made updates slow.

Users

Designers who maintain the system in Figma, and developers who implement it in Flutter and SwiftUI.

My role

I designed and built the pipeline end to end: extracting design values from Figma, generating components with an LLM agent, and verifying the result against the spec. I also wrote the project documentation for executives.

Key decisions

  1. Verify the LLM on both sides. LLM output varies between runs, so I checked the input spec and the generated code with deterministic comparisons (colors, dimensions, radius, typography).

  2. Fix problems in Figma, not in code. When a color did not exist in the design system, the pipeline stopped with an error instead of guessing, so inconsistencies could not spread quietly.

  3. Update with diffs, not full regeneration. A small design change produces a small, reviewable code change.

  4. Two ways to run it. A desktop app for semi-automatic runs, and a trigger that detects Figma changes and opens a merge request without anyone running it.

Outcome

Validation accuracy rose from 83.1% to 99.5%. A designer can now edit Figma and get a code update ready for review, instead of waiting for a developer to copy it by hand.

Tools

Figma MCP · LLM coding agent · Flutter · SwiftUI
